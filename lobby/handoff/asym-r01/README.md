## 文件与使用

- `slices/`：33 张 RGBA PNG，包括无 UI 的机库背景、10 个可分离的装甲组件（其中背景另计）、复用的卡框/费用牌/卡图占位，以及 12 个独立通用图标。准确数量和每张用途以 `slices.json` 为准。
- `layout.json`：1080×2340 重组坐标、图层顺序、文字独立层、图标颜色和原图转换。坐标为左上原点，rect 为 x/y/w/h。素材实际像素尺寸与显示 rect 分开记录。
- `slices.json`：每张素材真实宽高、RGBA alpha 极值、SHA-256、用途。`border` 顺序为左、下、右、上。
- `L01_reassembled.png`：使用实际独立切图、复用卡牌和完整 Noto Sans SC 文字重组的审查图，不是把效果图直接当底板。
- `contact-sheet.png`：透明棋盘格素材检查表。
- `source/`：保留聊天确认原图、生成式恢复的背景、去文字的透明装甲母图。
- `validation.json`：PNG 完整解码、尺寸、模式、散列和节点边界检查记录。

## 素材原则与限制（需审查）

1. 所有可变文字与数字均在 `layout.json` 中，由 TMP 或其他文本系统绘制，**没有烘焙到交付 sprites 中**。图标独立，主按钮、对手设置按钮、底部选中页签独立。BattleConsole 与 NavRail 为按钮/页签留透明孔，不可单独使用这些有孔底板而不装配子件。
2. 原图是 907×1734 的生成式概念图，没有 PSD 分层。被遮挡的机库和无文字装甲使用 imagegen 恢复，轮廓经显式遮罩提取，因此**不是逐像素无损拆分**。原图与重组预览都有保留，便于审图。
3. 新构图不再使用 32 文档旧 L01 的坐标。重组采用等比缩放到宽1080，并在上下加入深蓝安全区，避免非等比拉伸；具体映射在 layout.json。此布局是本次修改提出的新接入依据，待评审后再同步策划正文，未擅改正文或线框。
4. 卡框和占位图复用仓库 `ui/deck/handoff/armor-r02/sprites/`，像素未改动，清单 purpose 记录源名。自由卡采用已有 `Art_noart` 缺图占位；其他卡图仍为无IP几何/战术示意。通用图标为新绘的单色占位图标，不宣称与生成稿笔画完全一致。完整 Noto Sans SC 用于预览，不使用微软雅黑。
5. 装甲件形状不规则且有斜透视，首版按 **Simple/固定宽高比** 使用，border 全零表示明确禁用九宫格，不能任意拉伸。尚未制作按下/悬停/非选中衍生状态、9:16 自适应布局和 Unity 验证。不要把本包标成最终实机验收通过。
6. 导入建议：Sprite / Single、Full Rect、PPU 100、Bilinear、sRGB、Compression None、MipMap Off、Alpha Is Transparency On。背景不透明，其他图层按 alpha 合成。只有单色图标染色；装甲纹理保持白色 tint。头像图标本身为双色，不整图染色。
7. 无官方 Logo、机体立绘、内网截图；文字 Logo、几何头像、卡面均为占位。

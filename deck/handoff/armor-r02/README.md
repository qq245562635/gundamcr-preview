# 装甲整备终端 r02：S01 还原依据

视觉来源为 [本轮用户附图](../../mockups/r02/source/S01_approved.png)。先对照这张图，再看 [1080 × 2340 重组目标](../../mockups/r02/S01_main.png)。保留做旧装甲白、深蓝背景、蓝色费用牌、深色定位栏、白色名称条和黄色主按钮。

## 文件与用途

| 文件 | 用途 |
|---|---|
| `sprites/` | 从无文字材质母图提取的实际像素：底板、透明图窗卡框、占位图区、缺图底、战术图、页签、按钮等 |
| `layout.json` | 原生画布、十四张卡的位置 / 内容 / 图窗、每个文字层的中心与字号、角色颜色、字体与安全区调整 |
| `slices.json` | 每张素材真实尺寸、透明通道、用途、PPU、过滤和压缩设置；border 顺序左下右上 |
| `fonts/` | Noto Sans SC 子集，主字体名为 Armor UI Review；500 / 700 字重，附 OFL 与原版权声明 |
| `S01_native.png` | 830 × 1896 原生坐标下的重组结果 |
| `preview.html` | 无外部依赖的浏览器重组实现；字体内嵌，底图和卡牌来自同目录实际切图 |
| `preview-browser.png` | 本次实际浏览器预览的完整页面截图，证明独立卡牌与字体已加载 |
| `build-checks.json` | 画布、卡数、卡组费用、型号及实际标准色像素检查结果；不是 Unity 运行验证 |
| `validation.json` | 21 张素材的尺寸 / RGBA、透明图窗、字体覆盖、重复构建、预览和差分工具检查记录 |

预览可从仓库根目录运行 `python -m http.server --bind 127.0.0.1`，再打开 `DesignDocs/ui/deck/handoff/armor-r02/preview.html`。页面可叠加确认原图，也可导出浏览器重组图；这些控制只供检查，非游戏内 UI。

## 接入约束

1. 使用这里的材质像素，不让实现端重新用渐变、默认圆角框、另一套图标去近似装甲接缝、做旧和按钮边缘。所有 Image 默认白色 tint，避免二次染色改变材质。
2. Unity 导入：Sprite (2D and UI)、Full Rect、PPU 100、Bilinear、sRGB、Alpha Is Transparency 开、Mip Maps 关、Compression None。卡框为有透明图窗的完整像素组件，不能随意做九宫格拉伸；`border:[0,0,0,0]` 表示不使用九宫格，不是待填写。
3. `ScreenBase` 已去除所有卡牌和可读文字；不要用整张 S01 PNG 当游戏界面。底板中的固定装甲 / 页签槽可复用，卡牌、名称、费用、型号、数量和操作必须独立成对象。页面切换 / 滚动 / 状态变化不能只换一张整屏截图。
4. 坐标以左上角为原点。原生尺寸为 830 × 1896。对照画布是 1080 × 2340，转换系数在 JSON 中。若用 RectTransform：pivot `(0,1)`，anchorMin / anchorMax `(0,1)`，anchoredPosition `(x,-y)`，sizeDelta `(w,h)`。CardRoot 按 JSON 的 `rect` 对原生卡组件 187 × 268 缩放。
5. 卡牌层级顺序：CardRoot → 图区（`artRect`）→ CardFrame → CostText / RoleText / NameText / ResourceText 或 ModelText / MissingText → CountText。全部文字由 TMP 渲染，不烘焙入 Sprite。
6. 文字层给的是可见排版中心，非 TMP 默认基线。采用实际附带字体 / 对应 Noto Sans SC 字重，禁用自动缩字与自动换行；名称最长六字。先用 JSON 字号与中心，再对照图调 TMP 的内边距和基线，不通过替换字体掩盖基线偏差。模型和资源名左对齐，小队数量右对齐。
7. 字体子集只覆盖本轮内容，用于确认 / 还原样机。正式运行需用完整字体资源以覆盖未来卡名和文案，并保持相同字形、500 / 700 字重。字体授权来自 [官方 Noto CJK 字体许可证](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)。
8. 本轮实例沿用确认图的两套显示比例：出战卡与收藏卡高度不同。不要静默回退到旧需求 234 × 288 卡片或紫色宝石；如果策划希望统一尺寸，应先出对应修正版确认效果。
9. 9:16 按已定原则将底栏贴底、收藏区滚动；该分辨率还需独立布局和实机图确认，不能用这里的长屏 `ScreenBase` 强行缩放后宣称适配完成。完整九宫格 / 自适应切图在全部界面确认后统一出。

## 状态参数

常态 1；按下 0.95 / 亮度 0.9 / 100 ms；选中 1.08 / 青色 `#2FD3E0` 边光；替换候选 ±3° / 0.4 s；拖拽 1.1 / 加深阴影并留原位虚影；目标 1.05 / 金色描边；锁定为整卡灰度，保留费用和名称。C01 是静态状态图，晃动 / 呼吸 / 弧线互换仍须运行验收。

缺图四台：自由 `ZGMF-X10A`、精神力 `MRX-009`、基拉·多加 `AMS-119`、旗帜式小队 `SVMS-01O`。末位 O 不得改回 E。

## 必须交回的还原证据

- 1080 × 2340 的 Unity 原始截图，当前卡组与本轮原版一致；不包含编辑器工具栏，不在截图后缩放 / 移位 / 涂改。
- 与 `S01_main.png` 的 50% 叠加图和差分图；逐项看面板边缘、卡槽、文字基线、按钮、真实材质，不只看平均像素差。
- 常态通过后，再交选中、替换、缺图、小队数量的运行截图；9:16 另交短屏截图。
- 实现端交回截图前，不能把“Unity 还原验收”写为已完成。

仓库根目录运行：

```text
python tools/compare_deck_armor.py path/to/unity-capture.png --out path/to/comparison
```

脚本严格检查 1080 × 2340，不自动缩放或对齐来隐藏误差；输出叠加、差分和各区域 MAE / RMS。数值是定位差异的辅助，不替代视觉验收。当前仅检查过本仓库的素材重组预览，尚无 Unity 截图。
